# VelvetBloom — Telegram Bot + Mini App

Робочий демо-проєкт для портфоліо: Telegram-бот квіткової студії з каталогом букетів у форматі Mini App (Telegram WebApp). Три мови (EN/UK/RU), історія та активні замовлення, синхронізація мови між ботом і Mini App.

## Стек

- **Бот**: Node.js + TypeScript, [grammY](https://grammy.dev) (+ вбудований `session` для мови та замовлень користувача)
- **Mini App**: React + TypeScript + Vite, Tailwind CSS, Framer Motion
- Дані каталогу — статичний TS-файл (`webapp/src/data/bouquets.ts`), без бази даних — це demo-проєкт. Замовлення зберігаються в пам'яті процесу бота (session), теж без БД.

## Структура

```

│   │   ├── i18n.ts       # тексти й формат замовлень на EN/UK/RU
│   │   └── types.ts      # OrderPayload, StoredOrder, SessionData
│   └── scripts/
│       └── setup-profile.ts  # `npm run setup:profile` — ім'я/опис бота через Bot API
└── webapp/
    └── src/
        ├── i18n/
        │   ├── dictionary.ts   # UI-тексти на EN/UK/RU
        │   └── LangContext.tsx # читає ?lang= з URL, віддає {lang, t, locale}
        ├── data/bouquets.ts     # каталог букетів (назва/опис/склад — на 3 мови)
        ├── components/
        │   ├── RevealImage.tsx    # ефект "домальовування" деталей букета
        │   ├── Calendar.tsx       # кастомний анімований календар (лок. місяці/дні)
        │   ├── PetalsCanvas.tsx   # анімація пелюсток при підтвердженні

```

## Мова: бот → Mini App

1. `/start` (якщо мова ще не обрана) показує вибір мови — EN/UK/RU.
2. Обрана мова зберігається в `ctx.session.lang` (grammY session, в пам'яті процесу).
3. Кнопка «Каталог» у клавіатурі будується як `${WEBAPP_URL}?lang=${lang}` — тобто мова передається в Mini App просто через query-параметр URL.
4. У Mini App `LangProvider` читає `?lang=` при завантаженні й підтягує весь UI (тексти, назви букетів, місяці календаря, формат дати) з `webapp/src/i18n/dictionary.ts`.
5. Змінити мову можна кнопкою «🌐 Змінити мову» в головному меню бота.

## Мої замовлення / Активні замовлення

- При підтвердженні в Mini App (`sendData`) бот зберігає замовлення в `ctx.session.orders`.
- **«Мої замовлення»** — повна історія (усі замовлення, з позначкою статусу).
- **«Активні замовлення»** — тільки ті, де дата доставки сьогодні або в майбутньому.
- Це demo-логіка на in-memory сесії: замовлення живуть, поки живий процес бота (перезапуск бота = чиста історія). Для реального продакшену — заміна на БД, сама структура (`StoredOrder`) вже готова під це.

## Профіль бота (ім'я, опис, аватарка)

```bash
cd bot
npm run setup:profile
```

Скрипт виставляє через Bot API: ім'я, короткий і повний опис (EN/UK/RU кожен), список команд. **Аватарку через Bot API виставити не можна** — у Telegram немає такого методу для ботів. Завантажте квадратне зображення (наприклад, фото флористичної студії) через **@BotFather → `/setuserpic`** вручну.

## Запуск локально

### Найшвидший спосіб — одна команда

З кореня репозиторію (`NexuraDev`):

```bash
npm run prot:live
```

Сама піднімає Mini App, відкриває ngrok-тунель (або перевикористовує вже активний), підставляє `WEBAPP_URL` у `bot/.env` і стартує бота. Деталі — `scripts/dev-tunnel.mjs`.

### Вручну, крок за кроком

**1. Бот**
```bash
cd bot
npm install
cp .env.example .env
# впишіть BOT_TOKEN від @BotFather
npm run dev
```

**2. Mini App**
```bash
cd webapp
npm install
npm run dev
```
За замовчуванням Vite підніме дев-сервер на `http://localhost:5173`.

**3. Тунель для Telegram**

Telegram вимагає **публічний HTTPS**-URL для WebApp-кнопки:
```bash
npx ngrok http 5173
```
Скопіюйте виданий `https://...ngrok-free.dev` URL у `bot/.env` як `WEBAPP_URL`, перезапустіть бота.

> ⚠️ Vite 5 блокує запити з чужим `Host`-заголовком за замовчуванням — тому в `webapp/vite.config.ts` вже стоїть `server.allowedHosts: true`, інакше тунель поверне 403.

Для продакшену `webapp` збирається (`npm run build`) і роздається як звичайний static-сайт (Vercel/Netlify/Caddy) — тоді `WEBAPP_URL` вказує на постійний домен.

## Чому Mini App більше не "зависає з білим екраном"

Кілька накладених причин було виправлено разом:

- `tg.ready()`/`tg.expand()` тепер викликаються синхронно в `main.tsx` **до** першого рендеру React, а не в `useEffect` після — менше шансів зловити невстановлений viewport WebView.
- `min-h-screen` (`100vh`) замінено на `min-h-dvh` (`100dvh`) по всіх екранах — `100vh` в мобільних Telegram WebView відомо мапиться некоректно до стабілізації visual viewport.
- `index.html` тепер має інлайновий брендований фон (`#FBF6EE`) і текстовий плейсхолдер замість голого білого — навіть під час повільного завантаження JS користувач бачить бренд, а не "зависання".
- Прибрано зайвий `layout`-prop у картках каталогу (FLIP-розрахунки на 10 елементах одночасно — зайве навантаження на слабких Android WebView).
- Додано `ErrorBoundary` навколо застосунку — якщо все ж станеться неопрацьована помилка рендеру, користувач побачить кнопку «Перезавантажити» замість мовчазного білого екрана назавжди.

## Що показати на скріні/відео для портфоліо

- Вибір мови на старті бота (EN/UK/RU) і те, як вона підхоплюється в Mini App
- Каталог з фільтрами за приводом (день народження / весілля / просто так / романтика)
- Ефект "домальовування" деталей букета при наведенні/тапі (`RevealImage`)
- Кастомний анімований календар вибору дати доставки
- Анімацію пелюсток на екрані підтвердження замовлення
- Реальне повідомлення-підтвердження, що прилітає в чат бота після оформлення
- «Мої замовлення» / «Активні замовлення» в меню бота
